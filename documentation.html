1. How to Run the Game

The game is a single HTML file that runs entirely in a web browser — no installation, no server, no app store needed.

Requirements

  • Any modern web browser (Safari, Chrome, Firefox, Edge)
  • Works on iPhone, iPad, Android, Mac, or PC
  • No internet connection required after opening the file
  • No accounts, logins, or sign-ups

Running on iPhone (Recommended)

1
Transfer the file to your iPhone Email index.html to yourself, share via AirDrop, or save it to iCloud Drive / Google Drive.
2
Open in Safari Tap the file to open it. If prompted, choose "Open in Safari". The game is designed specifically for Safari on iOS.
3
Add to Home Screen (optional but recommended) Tap the Share button (box with arrow) → "Add to Home Screen" → "Add". The game will appear as a full-screen app icon named "Slack Security" on your home screen.
4
Play Launch from your home screen. It opens in full-screen mode (no browser toolbar) just like a native app.
💡 Add to Home Screen Tip When added to the iPhone home screen, the game runs in "standalone" mode — it hides the Safari address bar and looks exactly like a native iOS app. This is the intended experience.

Running on a Mac or PC

1
Locate the file Find index.html in the slack security game folder.
2
Double-click to open The file opens in your default browser automatically.
3
Resize for best experience Resize your browser window to roughly phone-width (375–430px wide) to simulate the iPhone layout, or use DevTools device emulation (F12 → device toolbar).

Sharing the Game

Share the index.html file with anyone. It is self-contained — all code, styles, and data are in that single file. No external dependencies or internet required.

✅ Progress is saved locally Scores and achievements are saved in the browser's localStorage. Progress persists between sessions on the same device and browser. Clearing browser data will reset progress.

2. How to Play

Getting Started

When you open the game, you land on the Home Screen. Tap "Start Learning" to go to the Topics screen, where you choose a category.

🏠 Home — scores & start
📚 Topics — choose a category
📊 Progress — achievements & stats

Choosing a Category

The Topics screen shows all 6 security categories. Each card shows:

  • The category name and icon
  • How many flashcards it contains
  • Your best score percentage (once you've played it at least once)

Tap any category to begin. You can play them in any order.

Flashcard Mode

This is the study/review mode. For each card:

1
Read the question on the front of the card (purple face)
2
Tap the card to flip it and reveal the answer (white face). The source article from help.slack.com is shown at the bottom.
3
Tap "Next" to advance to the next card, or "Prev" to go back.
4
After the last card, your results screen appears.

Quiz Mode

This is the test/challenge mode. Switch to it using the toggle at the top of the game screen. For each question:

1
Read the question in the question box.
2
Tap one of the 4 answer options. Answers are randomly generated — 1 correct answer and 3 plausible wrong answers drawn from other cards in the same category.
3
Instant feedback: correct answers turn green (+10 points), wrong answers turn red, and the correct answer is highlighted in green.
4
Tap "Next" to continue to the next question.
5
After all questions, see your score, percentage, and points earned on the results screen.
🔄 Switching Modes Mid-Game You can switch between Flashcard and Quiz mode at any point using the toggle at the top of the game screen. Your card position is remembered.

Results Screen

After completing a category you see:

  • A performance icon (🏆 90%+, 🎉 70–89%, 📚 50–69%, 💪 below 50%)
  • Your percentage score (quiz mode) or completion confirmation (flashcard mode)
  • Correct / incorrect counts and points earned
  • Option to Try Again or Back to Topics

5. Complete Card Inventory

All 40 flashcards are listed below for review and accuracy verification. Each card shows the question, the answer, and the specific help.slack.com article it was sourced from.

🔑 Authentication (7 cards)

Q1
What is Two-Factor Authentication (2FA) in Slack?
Answer
A security feature requiring users to enter both their password and a time-based verification code (from an authenticator app or SMS) when signing in.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q2
Can a Slack admin make 2FA mandatory for all workspace members?
Answer
Yes. Workspace owners and admins can require all members to enable two-factor authentication before they can access the workspace.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q3
What is SAML Single Sign-On (SSO) in Slack?
Answer
An enterprise authentication method that lets employees sign in to Slack using their company identity provider (e.g. Okta, Azure AD). It centralises access control and removes the need for a separate Slack password.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q4
Who can configure Single Sign-On in a Slack Enterprise Grid?
Answer
Only Org Owners can configure SSO — it is the most restricted authentication setting in Enterprise Grid.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q5
What is a session duration limit in Slack?
Answer
A setting that automatically signs members out after a defined period of inactivity, reducing the risk of unauthorised access on shared or unattended devices.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q6
Who can set session duration limits in Slack?
Answer
Workspace owners and admins can set session duration limits to control how long members stay signed in.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q7
Why is 2FA important for Slack accounts?
Answer
Even if a password is stolen or guessed, an attacker cannot sign in without also having the second factor (the verification code), significantly reducing account takeover risk.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)

🛡️ Access Control (8 cards)

Q8
What are the three core member roles in a Slack workspace?
Answer
Owner/Admin (highest privileges), Member, and Guest (most restricted). Enterprise Grid adds Org Owner and Org Admin above Workspace Owner.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q9
What is the difference between a single-channel guest and a multi-channel guest in Slack?
Answer
A single-channel guest can only access one specific channel. A multi-channel guest can be added to multiple channels but still cannot access public channels or workspace-wide features.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q10
Why should you use guest accounts for contractors, interns, and clients?
Answer
Guest accounts limit access to only the specific channels needed, preventing exposure to sensitive conversations, files, and workspace-wide data.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q11
What should you do when a team member leaves your organisation?
Answer
Deactivate their Slack account immediately to prevent continued access. On Business+ and Enterprise plans, SCIM provisioning can automate this via your identity provider.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q12
What is SCIM provisioning in Slack?
Answer
System for Cross-domain Identity Management — an automated protocol that syncs your company directory (e.g. Okta) with Slack to automatically provision or deactivate accounts when employees join or leave.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q13
Who can deactivate a member's account in Slack?
Answer
Only Workspace Owners and Admins can deactivate member accounts.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q14
Who can change another member's role in Slack?
Answer
Only Workspace Owners and Admins can change member roles.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q15
Who can reset all members' passwords in Slack?
Answer
This requires a Workspace Owner to change the default setting — it is owner-level only.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)

⚙️ App Permissions (6 cards)

Q16
By default, who can install apps in a Slack workspace?
Answer
By default, any member can install apps. Workspace owners should review and restrict this setting so only approved apps can be added.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q17
What is Slack App Approval?
Answer
A workspace setting (turned on by owners) that requires admin review and approval before any new app can be installed, preventing unauthorised third-party access.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q18
Who can turn on App Approval in Slack?
Answer
Turning on app approval requires a Workspace Owner to change the default setting.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q19
Who can set app management policies in Enterprise Grid?
Answer
Only Org Owners and Org Admins can set app management policies that apply across the entire Enterprise Grid organisation.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q20
Why is it risky to allow all members to install apps?
Answer
Third-party apps can request access to messages, files, and channels. Unvetted apps may exfiltrate data, contain malware, or have excessive permissions.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q21
What is an anomaly event in Slack's audit logs?
Answer
An event flag that indicates unexpected or suspicious app or user behaviour — such as an app accessing unusual volumes of data or a user signing in from an unexpected location.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)

🗄️ Data Security (7 cards)

Q22
Who can export data from Slack conversations?
Answer
Only Workspace Owners/Admins can export data. For private channels and DMs, the workspace owner must change the default setting. Enterprise Grid has dedicated Export Admin roles.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q23
What is a message retention policy in Slack?
Answer
A setting that automatically deletes messages after a specified period to comply with data governance rules. Org owners/admins set policies; members can only adjust if explicitly permitted.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q24
Who controls file retention settings in Enterprise Grid?
Answer
File retention is restricted exclusively to Org Owners and Org Admins.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q25
What is a Legal Hold in Slack?
Answer
A feature (Enterprise Grid) that preserves all messages and files for specific users or channels, preventing deletion — used for legal discovery and compliance.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q26
What are Slack's specialised system roles for data protection?
Answer
Enterprise Grid provides dedicated roles: DLP Admin (data loss prevention), Legal Holds Admin, Export Admin, and Audit Logs Admin — enabling least-privilege access without full admin rights.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q27
Can Slack admins control whether member email addresses are visible to others?
Answer
Yes. Admins can control whether member email addresses are displayed in user profiles, limiting data exposure.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q28
What does DLP stand for in Slack's Enterprise security model?
Answer
Data Loss Prevention. The DLP Admin system role manages policies that detect and prevent sensitive data (e.g. credit card numbers, PII) from being shared inappropriately.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)

🔍 Monitoring & Audit (6 cards)

Q29
What are Audit Logs in Slack?
Answer
A record of all significant events in your Slack organisation (sign-ins, file exports, permission changes, app installations) — available on Enterprise Grid for security monitoring.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q30
Who can access audit logs in a Slack Enterprise Grid?
Answer
Org Owners, Org Admins, and members assigned the Audit Logs Admin system role can access audit logs.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q31
What is the Slack Audit Log API?
Answer
An API that lets Enterprise Grid organisations programmatically retrieve audit events for integration with SIEM tools (like Splunk or Datadog) for automated threat detection.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q32
What is a SIEM tool and why integrate one with Slack?
Answer
Security Information and Event Management — software that aggregates logs from multiple systems. Integrating Slack audit logs with a SIEM enables automated alerting on suspicious activity patterns.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q33
What analytics are available on paid Slack plans?
Answer
Admins can access analytics dashboards showing member activity, channel engagement, and usage patterns — helping identify unusual behaviour.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q34
What should admins do to monitor invitation activity?
Answer
Periodically review both pending and accepted invitations to catch unauthorised access. Admins can also require admin approval for all new invitations.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)

🌐 External Collaboration (6 cards)

Q35
What is Slack Connect?
Answer
A feature that lets users collaborate with people at other organisations via shared channels — without granting them full membership in your own workspace.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q36
Why is Slack Connect more secure than inviting external users as full members?
Answer
Slack Connect keeps external collaborators in controlled shared channels only. They cannot access other channels, files, or workspace settings — limiting data exposure.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
Q37
Who can invite single-channel guests to private channels?
Answer
Only Workspace Owners and Admins can invite single-channel guests to private channels.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q38
What permissions do guest users NOT have in Slack?
Answer
Guests cannot: join public channels on their own, use @everyone, create channels (single-channel guests), or access workspace-wide features.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q39
What is domain claiming in Slack Enterprise Grid?
Answer
A feature allowing an organisation to claim ownership of an email domain, ensuring all workspace members with that domain are managed centrally. Only Org Owners/Admins can manage domain claiming.
Source: Slack Help: Permissions in a Slack workspace (help.slack.com/articles/201314026)
Q40
Why should you verify ownership of approved email domains in Slack?
Answer
If you enable auto-join for an email domain you do not own, people outside your organisation could gain unauthorised access to your workspace.
Source: Slack Help: Best practices for Slack security (help.slack.com/articles/115004155306)
